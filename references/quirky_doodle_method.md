# 怪诞小人风：长文拆解与一致性规则

用于 `quirky_doodle_character_flow`。这套规则的重点不是固定版式，而是稳定找到“值得画出来的核心动作”，再让小黑参与动作本身。小黑角色参考 `assets/examples/xiaohei/` 的内置校准样图；样图只用于稳定角色 DNA、线条密度、留白和颜色克制度，不用于复刻构图。


## 小黑角色 DNA（优先稳定）

生成怪诞小人风时，先稳定“小黑”，再发明隐喻：

- 小黑是黑色实心不规则小怪物，不是普通线稿小人。
- 眼睛是两个白色圆点；不要闪亮大眼、表情包眼或复杂五官。
- 身体像黑豆、黑盒、洞口、影子或机器里的黑块，轮廓轻微不规则。
- 胳膊腿很细、动作明确；可以笨拙，但不要卖萌。
- 表情空、呆、认真、冷幽默，像在白板草图里负责某个系统动作的操作员。
- 参考 `assets/examples/xiaohei/` 的角色比例和画面密度；不要复制其中的“断点、鱼、井、桥、压机、发酵”等具体案例。

## 先找认知锚点

读文章时不要平均按段落配图。优先找这些锚点：

- 核心判断：一句能改变读者理解的判断。
- 认知断点：旧方法失效、新方法出现、问题卡住的地方。
- 输入输出：信息、素材、任务如何进入系统并变成结果。
- 分流判断：按什么标准走向不同路径。
- 前后对比：混乱到有序、手动到自动、焦虑到稳定。
- 承接路径：内容、用户、反馈、结果如何被接住。
- 常见坑：漏掉、卡住、变重、绕路、断裂、假输出。
- 角色状态：创作者、用户、系统操作者从什么状态变成什么状态。

每张图只表达一个锚点；不要把多个观点拼成一张复杂大图。

## 配图策略字段

做文章拆图时，每张怪诞小人风图片至少想清楚：

- 放在哪个段落后
- 图的主题
- 核心意思
- 结构类型
- 小黑正在做什么
- 主隐喻物件是什么
- 建议元素
- 中文短标注

默认 4-8 张正文图；短文 1-3 张；长文也不要轻易超过 9 张，除非用户指定。

## 结构类型

每张图选择一种结构即可：

- Workflow 流程：输入 → 处理 → 输出，适合工作流和自动化链路。
- 系统局部：只画 3-5 个核心模块，适合过滤器、数据库、Agent 局部。
- 前后对比：左边混乱，右边稳定，中间用橙色箭头。
- 角色状态：2-4 个小状态，适合痛点、焦虑、卡住、跑起来。
- 概念隐喻：一个怪机器、黑盒、抽屉、漏斗、井、门或怪工位。
- 方法分层：一层层盒子或堆叠，不要正式金字塔。
- 地图路线：一条弯曲路径和少量节点。
- 小漫画分镜：2-4 个小场景，每格一个动作。

不要把结构类型写到画面上。

## 原创隐喻生成

1. 把抽象概念换成物理动作：卡住、漏掉、变重、分拣、沉淀、发酵、开门、折叠、拆包、回流。
2. 把系统换成低科技物件：旧机器、纸箱、抽屉、水管、邮筒、怪表盘、秤、井、梯子、线团、闸门、打孔器。
3. 让小黑承担动作：卡在机器里、拉错线、守门、搬运、修补、称重、扶梯子、记录、把材料塞进怪装置。

每次根据当前文章重新发明隐喻，不要复用旧图套路。

## 视觉一致性

- 16:9 横版正文配图。
- 纯白背景，不用纸纹、米色、渐变、噪点和复杂阴影。
- 黑色细线手绘，轻微抖动，不机械、不矢量。
- 主体占画面约 40%-60%，至少 35% 留白。
- 中文手写标注最多 5-8 处，每处 2-8 字。
- 黑色用于主体线稿和小黑；橙色用于主流程；红色用于问题、风险、提醒；蓝色用于反馈、系统状态或补充说明。
- 小黑是黑色实心不规则小怪物，白色圆点眼睛，细胳膊细腿，空表情、认真、冷幽默。
- 小黑必须承担核心动作。如果去掉小黑后画面隐喻仍完整，说明小黑只是装饰，需要重写。

## 禁止项

- 不要 PPT、正式流程图、课程课件、商业插画、儿童卡通。
- 不要真实 UI 截图或科技感界面。
- 不要复杂架构图、过多箭头、过多节点、过多文字。
- 不要左上角写“工作流 / 系统架构 / 常见坑 / 路线图”等类型标题。
- 不要固定左标题右图、固定三段式或固定模板；版式应由内容动作决定。

## QA

生成前后检查：

1. 这张图是否只讲一个核心锚点？
2. 小黑是否正在做核心动作？
3. 是否有新鲜但成立的物理隐喻？
4. 标注是否足够少、足够短？
5. 背景是否纯白、留白是否足够？
6. 第一眼是否“有点怪”，但 1 秒内能看懂结构？
