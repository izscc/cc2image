# 可视化研究所轴测图解方法论

来源参考：

- 可視化研究所：《どこまでも奥行きを描ける「アイソメトリック図法」その特徴と広がる用途を考える》  
  https://kashika-lab.co.jp/2024/09/19/isometric/
- 可視化研究所《CORPORATE PROFILE / 「絵本」案内 ver.》中的 Visualize / Storyboard / Mapping / Illustration / Branding 服务结构。

## 一句话方法

用统一投影规则，把复杂信息变成空间化、模块化、可组合、可协作的视觉系统。

轴测图解的价值不在于“看起来立体”，而在于：

1. 远近不缩放，信息关系更公平。
2. 统一角度和比例，适合系列化输出。
3. 对象可以模块化拼接，适合地图、流程、架构、服务说明和品牌插画体系。

## 适合什么时候使用

优先使用 `isometric_modular_system` 的场景：

- SaaS 产品功能总览。
- AI 工作流、自动化流程、Agent 系统架构。
- 城市、园区、工厂、仓库、办公室、数据中心、学习地图。
- 服务路径、用户旅程、课程路径、内容生产流水线。
- 多角色、多模块、多节点之间的关系说明。
- 品牌官网分类图、产品功能插画、企业服务说明。
- 需要多人协作保持统一风格的系列插画。

不优先使用的场景：

- 强情绪叙事。
- 单一人物肖像。
- 高真实感产品渲染。
- 需要强镜头感、强焦距、强景深或电影氛围的画面。
- 只表达一句抽象观点、没有空间或结构关系的主题。

## 核心流程

```text
定义信息任务
→ 判断是路径 / 结构 / 流程 / 空间 / 层级 / 数据关系
→ 选择轴测视角
→ 建立统一网格
→ 拆成模块组件
→ 分配顶面 / 左面 / 右面的信息职责
→ 控制视觉优先级
→ 嵌入文字和标注
→ 输出为可复用组件库或系列图
```

## 1. 投影规则先于细节

不要先问“画什么元素”，先问：这张图要解释什么关系？

- 路径：让道路、箭头、台阶、传送带成为主线。
- 结构：让模块、楼层、堆叠关系成为主线。
- 流程：让输入、处理、输出按空间方向排列。
- 地图：让顶面承载路线、区域和节点。
- 架构：让平台、盒子、连接线和接口构成系统。

原则：角度先于风格，结构先于装饰。

## 2. 无透视缩放，保证信息公平

轴测图解不追求真实镜头，而追求清晰空间：

| 普通透视 | 轴测图解 |
| --- | --- |
| 更像真实观看 | 更像结构说明 |
| 远处会变小 | 远近比例稳定 |
| 氛围优先 | 理解优先 |
| 适合沉浸叙事 | 适合关系、路径、层级 |

生成提示词时要明确：

- no perspective shrinkage / no dramatic perspective。
- 所有模块服从同一套等距轴线。
- 不要强景深，不要近大远小的镜头效果。

## 3. 三面分工：顶面、左面、右面

把每个物体当成一个信息容器，而不只是形状。

```text
顶面：路径、地图、平面关系、主流程、区域划分
左面：结构、层级、堆叠、阶段、系统状态
右面：标签、补充信息、指标、入口、交互点
```

示例：

- 一个平台的顶面画用户路径。
- 左侧面标注“输入 / 处理 / 输出”。
- 右侧面贴功能标签或状态灯。

## 4. 视角角度服务表达重点

不要问“哪个角度好看”，而问“哪个角度最能让读者理解”。

| 目标 | 视角选择 |
| --- | --- |
| 展示建筑、人物、立体物 | 低视角，侧面更明显 |
| 展示地图、路线、全貌 | 高视角，顶面更明显 |
| 做品牌系列 | 中性视角，比例均衡 |
| 做空间流程图 | 让路径所在平面最清楚 |
| 做系统架构 | 中高视角，模块边界清楚 |

建议字段：

- `isometric_angle`: 高视角 / 中性视角 / 低视角。
- `grid_rule`: 统一 30°/30° 等距网格，或统一轴测斜网格。
- `main_plane`: 顶面 / 左面 / 右面哪个承载核心信息。

## 5. 模块化搭积木

所有对象先拆成基础组件：

```text
方块、平台、墙面、楼层、台阶、路径、传送带、门、窗口、管道、桥、人物、图标、标签、浮动信息卡片
```

每个组件都要能复用，而不是一次性画死。

适合沉淀的组件库：

- 建筑组件。
- 人物组件。
- 路径组件。
- 数据组件。
- 交通组件。
- 设备组件。
- 标签组件。
- 背景组件。

## 6. 文字嵌入空间，但不牺牲可读性

文字不是后贴标签，也不是为了炫技乱贴到斜面上。

规则：

- 大标题保持正向阅读。
- 短标签可以贴合斜面。
- 数字和指标优先清晰。
- 装饰文字可以顺应空间面。
- 说明文字不要过度倾斜。
- 中文短标签尽量 2 到 6 字。

一句话：文字服务信息，不服务立体效果。

## 7. 视觉优先级控制

轴测图容易变成“所有东西都很可爱，但不知道看哪里”。必须控制优先级。

四个变量：

```text
尺寸：重要对象更大
位置：核心对象放中心或前景
颜色：重点用高对比色
线条：重点对象描边更清晰
```

禁止：

- 所有模块同等显眼。
- 到处都是人物和装饰。
- 路径、标签、图标互相抢重点。
- 过度 3D、过度写实、强景深。

## cc2image 结构化字段建议

当使用 `isometric_modular_system` 时，优先补齐：

```json
{
  "information_task": "路径 / 结构 / 流程 / 空间 / 层级 / 数据关系",
  "target_reader": "目标读者",
  "isometric_angle": "高视角 / 中性视角 / 低视角",
  "grid_rule": "统一等距轴线 / 统一斜网格",
  "main_plane": "顶面 / 左面 / 右面",
  "modules": ["模块1", "模块2", "模块3"],
  "path_or_relation": "核心路径或关系",
  "priority_object": "第一视觉重点",
  "labels": ["短标签1", "短标签2", "短标签3"],
  "component_reuse_notes": "哪些对象可复用为组件库"
}
```

## 最终质量检查

1. 是否先定义了信息任务，而不是先选装饰？
2. 所有对象是否服从同一套轴测网格？
3. 是否避免近大远小和强透视？
4. 顶面、左面、右面是否各有信息职责？
5. 第一视觉重点是否明确？
6. 标签是否少、短、清楚？
7. 是否能作为系列图继续扩展？
8. 是否适合后续拆成组件库？
