## 总原则

cc2image 不应只问“画什么风格”，而要先问：

```text
这张图要承担什么解释责任？
它需要多准确、多亲近、多品牌化、多可复用、多能引发兴趣？
```

可视化研究所的价值在于：把“好看/不好看”的感性判断，转成可讨论、可选择、可复用的设计参数。

---

## 1. 解释度滑杆：从图解到世界观

文章提出“说明性”不是 0 或 100，而是一条可调节的梯度。cc2image 可以把它变成 `explanation_level` 字段。

```text
5｜图解型：谁、何时、什么、关系、结果都清楚；适合手册、教材、数据事实。
4｜夸张型：保留结构，但放大一个重点；适合封面、广告、主张表达。
3｜场景型：补充前后情境，让读者有代入；适合服务介绍、案例、故事板。
1｜世界观型：解释责任最低，氛围和余韵最高；适合书封、品牌海报、主视觉。
```

使用规则：

- 正文知识图、教程、数据图：默认 5 或 4。
- 小红书封面、文章头图：默认 4。
- 用户故事、客户案例：默认 3。
- 品牌主视觉、情绪海报：默认 1 到 3。

生成提示词时要写清：

```json
{
  "explanation_level": 4,
  "must_be_understood": ["核心关系", "主路径", "关键结论"],
  "can_be_ambiguous": ["背景情绪", "附属场景"]
}
```

## 2. 先做信息整理，再做符号化

可视化研究所把“传达性”拆成两个步骤：

```text
信息整理 → 关键词符号化
```

### 信息整理

先把内容压缩成一段短要约，再从中抽取：

- 人：谁在行动？
- 物：关键对象是什么？
- 状态：现在处于什么状态？
- 变化：发生了什么转变？
- 关系：对象之间是并列、因果、嵌套、分流还是循环？
- 时间：是否跨越多个阶段？
- 地点：是否跨越多个空间？

如果时间或地点超过 1 个，不要硬塞成单张场景，优先改成：

- Storyboard。
- 分镜漫画。
- 横向流程。
- 前后对比。
- 轴测空间路径。

### 符号化

关键词不要直接照字面画，要做“语义距离选择”：

```text
具体实物 → 典型图标 → 抽象符号 → 情绪/光/空间隐喻
```

例如：

```text
想法 → 大脑（具体但可能生硬）→ 灯泡（典型）→ 光（抽象）→ 门缝里的光（世界观）
```

cc2image 应输出：

```json
{
  "keyword": "想法",
  "symbol_options": ["大脑", "灯泡", "光", "门缝里的光"],
  "chosen_symbol": "灯泡",
  "reason": "兼顾易懂和亲和，不会过于生理化"
}
```

## 3. 插画价值雷达：7 个评估轴

把“好不好看”改成“是否服务目的”。每张图可按 7 个轴自检：

1. `tone_manner_fit`：是否贴合品牌色、线宽、质感和长期调性？
2. `target_fit`：目标读者是否接受这个变形程度和信息密度？
3. `reusability`：是否能拆成组件，复用于封面、正文、海报、社媒、PPT？
4. `memorable_symbol`：是否有能被记住的主符号、角色或一句话？
5. `unique_information`：是否提供了正文没有重复讲的新增信息或关系？
6. `humor_hook`：是否有轻微的发现感、趣味、反差或视觉钩子？
7. `accessibility_safety`：是否避免色弱不可读、误解、冒犯、缺损误读和敏感符号？

默认不需要 7 项全满，而是按任务类型加权：

```text
手册/教程：解释度、安全性、目标适配权重最高。
品牌主视觉：调性、记忆符号、复用性权重最高。
社媒封面：记忆符号、趣味钩子、标题可读性权重最高。
数据图：准确性、中立性、来源透明权重最高。
系列图：复用性、调性、角色一致性权重最高。
```

## 4. 数据可视化：事实不被风格扭曲

Kashika-Lab 的信息图服务强调：数据和视觉表达必须准确整合，避免图形与数值错配。

cc2image 处理数据主题时，必须先补齐：

```json
{
  "data_source": "来源",
  "metric": "指标",
  "comparison_axis": "比较维度",
  "time_range": "时间范围",
  "visual_claim": "这张图允许表达的结论",
  "forbidden_claims": ["不能从数据推出的结论"]
}
```

原则：

- 不把相关性画成果因。
- 不用面积、人物数量、图标大小制造错误比例。
- 如果是灵感型表达，要明确“观察入口”，不要装作严格统计图。
- 数据图可以有情绪入口，但必须保留来源、维度和可核查路径。

## 5. 从“数据图表”到“观察机制”

在情绪数据案例中，Kashika-Lab 将多条折线数据映射成人物动作的可动域，让读者先观察，再追溯机制和数据来源。

这可以转成 cc2image 的“数据动作映射”模式：

```text
变量 → 视觉参数 → 观察感受 → 机制说明 → 数据来源
```

例子：

```text
快乐 → 头部上扬
焦虑 → 身体前倾
愤怒 → 手臂摆动幅度
期待 → 步幅变大
```

静态图中可以做成：

- 一组角色姿态对比。
- 参数面板 + 角色动作。
- 小 multiples 多格状态图。
- “不要先下结论”的观察型信息图。

关键：图像只提供观察线索，不替用户做武断判断。

## 6. 漫画共感型信息图

对于问卷、调研、用户反馈这类数据，不一定要直接画柱状图。可以把“问题和比例”转成“共感场景”：

```text
问卷题目 → 主人公行为场景
同意/增加比例 → 共感率
高排名选项 → 主线剧情
低排名选项 → 辅助道具或背景细节
减少项/负向项 → 作为故事转折或隐含背景
```

适合：

- 用户洞察报告。
- 消费趋势。
- 生活方式调研。
- 社群反馈。
- 疫情、社会变化、职场状态等需要同理心的主题。

注意：

- 主人公尽量中性，减少性别/年龄/职业偏见。
- 标注“共感率”比直接“支持率”更适合漫画叙事，但必须说明转换逻辑。
- 因为漫画会固定印象，所以最好与原始数据或图表一起使用。

---

## 7. 角色解像度：让角色能持续行动

角色不是头像，而是一套能预测行为的设定系统。要让角色在系列图中稳定出现，至少补齐：

```json
{
  "name": "角色名",
  "age_or_stage": "年龄/阶段",
  "role": "角色职责",
  "personality": "性格",
  "habit": "习惯动作",
  "catchphrase": "口头禅",
  "values": "价值观",
  "visual_rules": "外观规则",
  "can_do": ["可做动作"],
  "cannot_do": ["禁用动作/禁用设定"]
}
```

用于 cc2image：

- 系列正文图的连续小角色。
- 品牌 guide character。
- 教程图的讲解员。
- 情绪漫画中的固定主角。
- AI 工作流图中的“执行者”。

---

## 8. 可分解交付：一张图也要像资产库

Kashika-Lab 案例中强调，插画可以按区域、人物、图标拆分，便于再配置到广告、网站、资料中。

cc2image 的批量图应增加：

```json
{
  "reusable_parts": ["角色", "图标", "背景模块", "路径", "标签样式"],
  "series_rules": {
    "color": "主色/辅助色/强调色",
    "line": "线宽/圆角/阴影",
    "character": "角色比例/表情/动作范围",
    "label": "标签长度/字体/位置"
  },
  "reuse_scenes": ["公众号头图", "正文配图", "PPT", "海报", "网站模块"]
}
```

这会把 cc2image 从“单次生成图片”提升到“生成可运营的视觉资产系统”。
